What the pipeline does with your file

  1. Stream, don't load: 8MB slices keep the tab responsive; .gz decompresses in-browser via DecompressionStream. A 50MB mobile guard and a 500MB desktop confirm protect small devices.
  2. Detect per line: JSON array, JSONL/NDJSON, Apache Combined, Nginx default, W3C Extended (uses your #Fields header — without it, guess-mode parses but edge-rule generation is blocked to prevent acting on wrong columns), AWS ALB, Cloudflare Logpush.
  3. Analyze at scale: past 20k rows a Web Worker runs the 14-step pipeline; past ~300k lines a systematic 1-in-N sample keeps analysis honest, with an on-screen banner stating stride, kept/total counts, and timing.
  4. Render 10 modules: Bots → Verification → Crawl Budget → Costs → AI Matrix → Edge + Policy Bundle → Performance + Traffic → Dynamics → Security → CFO, plus Crawl+GSC join and local history.

When to leave the browser

  • 500MB–50GB: node tools/cli.js --exact --in access.log --out summary.json — exact full-file totals, no sampling.
  • 50GB+: the BigQuery pack (DDL + 5 queries + R2→Parquet streaming + scheduled UNVERIFIED-% query) in Tab 6 / BIGQUERY.md.
  • Test data: pick a URL range in the tool (0–100 … 1M–10M, each with max-size estimate) or npm run gen-logs -- --lines N --out file.jsonl (deterministic seeds).

FAQ

1GB upload fails? Use a modern desktop browser (not a phone), accept the >500MB confirm, stay on the tab. You will see Reading % then analysis %. Costs describe the analyzed sample and scale ~Nx — the banner says exactly how much.

"No valid records found"? The error reports lines seen + detected format. Compare your first line with the How To Use examples — usually a custom column order (add a #Fields header) or a truncated download.

Is sampling honest? The banner shows stride, kept/total lines, and read time; verification counts are scaled and labeled. No silent extrapolation anywhere.
