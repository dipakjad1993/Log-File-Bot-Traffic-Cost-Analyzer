Block training bots without losing AI citations

The classic mistake: one rule blocks "AI bots" and kills ChatGPT/Perplexity citations for 2 weeks. The fix: split training (block) vs search-index (allow 120/min) vs user-triggered (never throttle) — exactly what the analyzer's 127-signature DB (49 training, 10 search-index, 8 user-triggered) enforces end to end.

1. robots.txt split (RFC 9309 most-specific-wins)

Training blocked, search allowed — paste as-is
User-agent: GPTBot Disallow: / User-agent: ClaudeBot Disallow: / User-agent: CCBot Disallow: / User-agent: Bytespider Disallow: / User-agent: Google-Extended Disallow: / User-agent: OAI-SearchBot Allow: / User-agent: PerplexityBot Allow: / User-agent: Claude-SearchBot Allow: / User-agent: DuckAssistBot Allow: / User-agent: * Allow: /

Notes from the field: Google-Extended is a robots token, not a user-agent — it only works here, never in a WAF rule. ChatGPT-User / Perplexity-User ignore robots ~54% of the time (they're user-triggered fetches), so robots.txt is not their control plane — edge policy is. 2. Cloudflare WAF rules (plus Fastly + AWS equivalents)

Rule 1 — training bots: Managed Challenge, 60/min (20 aggressive)
(http.user_agent contains "GPTBot") or (http.user_agent contains "ClaudeBot") or (http.user_agent contains "CCBot") or (http.user_agent contains "Bytespider") or (http.user_agent contains "GoogleOther") or (http.user_agent contains "Meta-ExternalAgent") or (http.user_agent contains "DeepSeekBot") or (http.user_agent contains "QwenBot") => Managed Challenge. Repeat offenders => Block.
Rule 2 — search-index: ALLOW, rate-limit 120/min, 429 + Retry-After only
(http.user_agent contains "OAI-SearchBot") or (http.user_agent contains "PerplexityBot") or (http.user_agent contains "Claude-SearchBot") or (http.user_agent contains "DuckAssistBot") => ALLOW. Rate limit 120/min/IP; excess => 429 + Retry-After: 30. NEVER Block.
Rule 3 — user-triggered: DO NOT throttle
(http.user_agent contains "ChatGPT-User") or (http.user_agent contains "Perplexity-User") or (http.user_agent contains "Claude-User") => ALLOW + log. Abuse ceiling 300/min => 429 + Retry-After: 10.

Rate control uses 429/503 + Retry-After — the analyzer never generates tarpitting rules. 3. Roll out safely: monitor → challenge → block

  1. Week 1 — monitor: deploy Rule 1 in Log/Managed-Challenge-bypass mode. Read Tab 8 · Dynamics for bursts and Tab 2 · Verification for VERIFIED vs spoof share.
  2. Week 2 — challenge: enforce Managed Challenge on training. Watch citation dashboards (not crawl volume) for OAI-SearchBot/PerplexityBot — they must stay untouched.
  3. Week 3+ — block: convert repeat training offenders to Block. Keep search-index on 120/min forever; review Bot Dynamics monthly against deploys.
  4. Never: hard-block search-index, throttle user-triggered, or Disallow OAI-AdsBot (revenue risk on ecommerce).

FAQ

How fast do citations recover if I already blocked search? Typically 1–2 weeks after re-allowing at 120/min, once fetch volume normalizes. Watch Tab 8 for the recovery curve.

Do these rules cover the 2026 surge bots (DeepSeek, Qwen, Firecrawl)? Yes — all classified training in the 127-signature DB with 60/min policies. Re-run the analyzer after each weekly DB refresh.
