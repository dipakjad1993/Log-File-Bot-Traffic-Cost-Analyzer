PerplexityBot: block or allow?

Allow — at 120/min. PerplexityBot is search-index with the best measured crawl-to-referral in the DB (~210:1 vs OAI 85:1, Claude ~5,143:1). Hard-blocking it trades pennies of bandwidth for lost AI-answer citations. Throttle training bots (GPTBot, CCBot, Bytespider) instead.

1. Why the math favors allow

Every 210 Perplexity fetches correspond to roughly one referral visit — by far the cheapest AI crawler per unit of returned traffic. In the 10k pinned fixture PerplexityBot made 251 requests / 9.7 MB: a few cents of CloudFront egress against citation-bearing answer traffic. Compare Claude-SearchBot (~5,143:1, still allowed because citations compound) and raw training crawlers (no referrals at all — pure cost).

2. Copy-paste rule

robots.txt — search-index stays allowed
User-agent: PerplexityBot Allow: /
Cloudflare — rate-limit, never block
# PerplexityBot: ALLOW, 120/min/IP # excess => 429 + Retry-After: 30 — NEVER Block # Perplexity-User (user-triggered): do NOT throttle (300/min abuse ceiling only)

3. Verify it's really Perplexity (spoof check)

  • Vendor IP JSON: perplexity.ai/perplexitybot.json (+ legacy docs.perplexity.ai/bot.json), snapshotted with full CIDRs + IPv6 in data/bot-ips.json (2026-09-17, 14 sources). IP match = VERIFIED.
  • UNVERIFIED PerplexityBot on a residential/cloud IP with a browser UA = spoof — challenge it, and export the rDNS checklist from Tab 2 before blocking.
  • Perplexity-User is user-triggered fetch (live answers), verified separately via perplexity.ai/perplexity-user.json — robots.txt may not even apply to it.

FAQ

Perplexity crawls aggressively — isn't that reason to block? Aggression is a rate problem, solved by 120/min + 429. Blocking is a visibility decision with 2-week citation consequences. Rate-limit first, measure, then decide.

What about Perplexity-User? Never throttle. It's a live user waiting for an answer; a 429 is a missing citation, not saved bandwidth.
